# 초기 하드웨어 세팅 과정

## 문서 목적

초기 하드웨어 설치와 네트워크 세팅 과정을 정리한다.

본 문서는 초기 On-prem 물리/네트워크 설계 내용을 기준 정보로 사용한다. 최신 기준은 [../architecture/current-architecture-summary.md](../architecture/current-architecture-summary.md)를 우선하며, 실제 설치 과정, 화면 캡처, 명령어, 시행착오 내용은 이후 별도로 보강한다.

## 작업 범위

- PC 5대 Proxmox VE 설치
- 물리 네트워크 유선 LAN 구성
- 라우터 IP 대역 설정
- pfSense VM 설치 및 IP 대역 설정
- pfSense VLAN 설정
- 테스트 VM을 통한 IP 할당 검증
- VLAN 방화벽 정책 보류 사항
- PVE 10G 클러스터링

## 2. 물리 네트워크 유선 LAN 구성

### 기준 정보

| 구분                  | 대역             | 용도                                                     |
| --------------------- | ---------------- | -------------------------------------------------------- |
| 1G 물리 관리망        | `172.16.30.0/24` | 상위 라우터, 관리형 스위치, pfSense WAN, Proxmox 관리 IP |
| 10G 스토리지망        | `10.10.10.0/24`  | Proxmox/Ceph 스토리지 백엔드                             |
| pfSense VLAN 서비스망 | VLAN 10/20/30/40 | VM, Kubernetes, DB, 관리용 서비스망                      |

- 1G 관리망과 10G 스토리지망은 분리한다.
- VM 서비스 IP는 `10.10.10.0/24`가 아니라 pfSense VLAN 대역을 사용한다.
- `10.10.10.0/24`는 Proxmox host가 Ceph storage backend에 접근하는 용도로 유지한다.

### 작업 과정

- 참고문서 [네트워크 구조 문서](../assets/물리-네트워크-구조.md)

## 3. 라우터 IP 대역 설정

### 기준 정보

| 항목              | IP            | 용도                        |
| ----------------- | ------------- | --------------------------- |
| Upstream Router   | `172.16.30.1` | 외부망/WAN uplink           |
| Management Switch | `172.16.30.2` | 1G 관리형 스위치 관리 IP    |
| pfSense WAN       | `172.16.30.3` | 상위 라우터 방향 인터페이스 |

- 상위 라우터와 Proxmox 물리 관리망은 `172.16.30.0/24`를 사용한다.
- pfSense WAN은 1G 물리 관리망에 연결하고, 상위 라우터를 통해 외부 통신을 수행한다.

### 작업 과정

- LAN선 설치후 관리자용 pc에서 작업수행
- 라우터 ip 인 `172.16.30.1` 로 웹 gui 접속 후 LAN ip 를 `172.16.30.0/24` 로 설정

## 6. pfSense VLAN 설정

### 기준 정보

| VLAN             | 대역             | 역할                                  |
| ---------------- | ---------------- | ------------------------------------- |
| VLAN 10 Public   | `172.16.41.0/24` | 외부 접근 서비스, Ingress, MetalLB    |
| VLAN 20 DMZ      | `172.16.42.0/24` | HAProxy, Keepalived, reverse proxy    |
| VLAN 30 Internal | `172.16.43.0/24` | Kubernetes node, MariaDB, 내부 서비스 |
| VLAN 40 Admin    | `172.16.44.0/24` | Bastion, monitoring, ArgoCD 관리 접근 |

| VLAN 40 테스트 VM | `172.16.44.0/24` |

### 테스트 실행 과정

- pve1 에서 test-vm 4개 설치
- proxmox gui 에 hardware-network device에서 VLAN tag 값을 각 vm 에 VLAN10~40 까지 설정해줌
- 설정후 vm 진입시 각각 설정한 VLAN 값에 맞는 ip 가 할당되었는지 확인함
- **pve1 에서 다음과 같은 설정은 꼭 해줘야함!**
- pve1에 `/etc/network/interfaces` 에 다음과같이 설정

```
auto vmbr0
iface vmbr0 inet static
        address 172.16.30.11/24
        gateway 172.16.30.1
        bridge-ports nic0
        bridge-stp off
        bridge-fd 0
        bridge-vlan-aware yes
        bridge-vids 2-4094
```

- 그래야 pfsense 에서 우리가 원하는대로 정상적인 라우팅 즉 pfsense 에서 할당하는 ip 를 각 하위 노드들이 받아서 사용하게함

## 8. VLAN 방화벽 정책 보류 사항

### 기준 정보

- pfSense가 VLAN 간 라우팅, NAT, 방화벽 정책을 담당한다.
- 현재 문서에서는 VLAN 방화벽 정책 상세 설정은 보류한다.
- 추후 Kubernetes, DB, Bastion, 관리 서비스 접근 흐름이 확정된 뒤 VLAN 간 허용 정책을 정리한다.

### 작업 정보

- 기준에 맞는 VLAN 값을 설정해주고 작업시 관리자용 pc 가 40번에 할당되어서 접근이 제한되는 경우가 종종 있음 따라서 보안 방화벽 정책은 일단 보류한뒤 추후에 작업하기로 함

## 9. PVE 10G 클러스터링

### 기준 정보

| 항목          | 기준                                                   |
| ------------- | ------------------------------------------------------ |
| 물리 구조     | Spine-Leaf                                             |
| NIC 구성      | 각 PC 10G NIC 2개 LACP bonding                         |
| MTU           | 9000 jumbo frame, 전 구간 동일 적용                    |
| 스토리지 대역 | `10.10.10.0/24`                                        |
| 용도          | Proxmox/Ceph storage backend, OSD replication/recovery |

- 10G 대역은 VM 서비스망으로 사용하지 않는다.
- VM disk는 Proxmox storage 설정을 통해 Ceph 위에 둘 수 있다.
- Kubernetes에서 Ceph CSI를 직접 사용할 경우에는 별도 네트워크 또는 라우팅 설계를 추가로 검토한다.

### 작업 과정

- 각 pve `/etc/network/interfaces` 에서 vmbr1 에 10G ip 를 설정해줌

```
auto lo
iface lo inet loopback

iface nic0 inet manual

auto vmbr0
iface vmbr0 inet static
        address 172.16.30.11/24
        gateway 172.16.30.1
        bridge-ports nic0
        bridge-stp off
        bridge-fd 0
        bridge-vlan-aware yes
        bridge-vids 2-4094

#2. 10G NIC
iface nic1 inet manual
        mtu 9000

auto vmbr1
iface vmbr1 inet static
        address 10.10.10.39/24
        bridge-ports nic1
        bridge-stp off
        bridge-fd 0
        mtu 9000

iface nic2 inet manual


source /etc/network/interfaces.d/*
```

- 모든 pve 의 `/etc/hosts` 에 hostname 추가

```
172.16.30.11 kosa-team3-01.co.kr kosa-team3-01
172.16.30.12 kosa-team3-02.co.kr kosa-team3-02
172.16.30.13 kosa-team3-03.co.kr kosa-team3-03
172.16.30.14 kosa-team3-04.co.kr kosa-team3-04
172.16.30.15 kosa-team3-05.co.kr kosa-team3-05
```

- pve 1 에서 클러스터 생성
  `pvecm create kosa-cluster --link0 10.10.10.39`
- 확인

```
pvecm status
cat /etc/pve/corosync.conf
```

- 각 노드에서 해당 클러스터로 조인
  ` pvecm add kosa-team3-01 --link0 10.10.10.[해당 노드 10G 대역 ip]`
- gui 에서 클러스터링 잘 되었는지 확인함
- Cli 에서 확인하는 법
  `cat /etc/pve/corosync.conf`
- 결과

```
ring0_addr: 10.10.10.39
ring0_addr: 10.10.10.40
ring0_addr: 10.10.10.41
ring0_addr: 10.10.10.42
ring0_addr: 10.10.10.43
```
